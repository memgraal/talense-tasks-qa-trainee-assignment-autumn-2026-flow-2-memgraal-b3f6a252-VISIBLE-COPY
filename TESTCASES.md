# Тест-кейсы API

Проверки относятся к API-части задания 2.1. Все тестовые имена и объявления создаются динамически. Для защищённых проверок создаётся пользователь набора; отдельный позитивный тест регистрации дополнительно создаёт собственную учётную запись. Каждый тест объявления создаёт собственные данные. Удаление объявлений выполняется в `tearDown`, в том числе после ошибки проверки.

## Регистрация и авторизация

| ID | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| API-01 | Сгенерированы уникальные username и пароль | Отправить `POST /api/1/register` с обоими полями | HTTP 201; JSON содержит непустой `id` и переданный `username` |
| API-02 | Пользователь набора уже зарегистрирован | Повторно зарегистрировать тот же username | HTTP 409; дубликат не создаётся |
| API-03 | API доступно | Отправить регистрацию без username и с пустыми учётными данными | HTTP 400 или 422; некорректные данные не принимаются |
| API-04 | Пользователь зарегистрирован | Отправить `POST /api/1/autorize` с верными данными | HTTP 200; `accessToken` непустой, `tokenType` равен `Bearer` |
| API-05 | Пользователь зарегистрирован | Авторизоваться с неверным паролем | HTTP 401; токен не выдан |

## Доступ и объявления

| ID | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| API-06 | Есть пользователь, токен и объявление этого пользователя | Без Authorization вызвать создание, чтение объявления, список продавца, обе статистики и удаление | Каждая защищённая ручка отвечает HTTP 401/403; существующее объявление не изменено и не удалено |
| API-07 | Есть валидный bearer-токен пользователя A | Создать объявление с `sellerID` пользователя B | Запрос отклонён HTTP 400/403/422; чужое объявление не создаётся |
| API-08 | Есть валидный bearer-токен пользователя A | Передать `X-UserId` пользователя B и `sellerID` пользователя B | Запрос отклонён; заголовок не позволяет подменить пользователя |
| API-09 | Есть валидный bearer-токен | Создать объявление и запросить его по UUID, затем запросить список своего продавца | Создание HTTP 200 с UUID; чтение и список HTTP 200; `name`, `price`, `sellerId`, `statistics` совпадают с отправленными данными |
| API-10 | Есть валидный bearer-токен | Дважды создать объявления с одинаковыми `name`, `price`, `sellerID`, `statistics` | Оба запроса успешны; UUID объявлений различаются |
| API-11 | Создано объявление со статистикой | Вызвать `GET /api/1/statistic/{id}` | HTTP 200; возвращены сохранённые значения статистики |
| API-12 | Создано объявление со статистикой | Вызвать `GET /api/2/statistic/{id}` | HTTP 200; возвращены сохранённые значения статистики |
| API-13 | Создано объявление | Удалить его через `DELETE /api/2/item/{id}`, затем повторно запросить | Удаление HTTP 200; удалённый UUID больше не возвращает объявление |
| API-14 | Есть валидный bearer-токен | Запросить объявление с UUID неправильного формата | HTTP 400/404; сервер не возвращает 5xx |
| API-15 | Есть валидный bearer-токен | Запросить случайный UUID, которого нет в созданных данных | HTTP 404 либо HTTP 200 с пустым массивом; чужие данные не возвращаются |

Нефункциональные аспекты проверяются через отказ в доступе без bearer-токена, защиту от подмены продавца, согласованность значений между созданием и чтением, уникальность UUID и обработку неверного идентификатора без серверной ошибки. Нагрузочные проверки не выполняются на общем стенде.

## Запуск

`python -m unittest -v test_api.py`
